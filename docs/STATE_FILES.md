# The state-directory contract

A trading bot that writes these files gets the Pace, Grid, Regime, Metrics, Fills and Reports
pages, the EOD report and a Health page fed from its own equity — without the desk ever
touching the bot's code or its broker connection. Everything is append-only JSONL (one row per
snap) plus one JSON of open positions; the desk re-reads on a slow timer and on the header ↻.

```
positions.json           open positions (the blotter shape, with avg_fill_price per leg)
ledger.jsonl             fills: open/close per ticket, per-leg DECISION bid/ask at submission, fill,
                         intended_limit, fill_net (signed net: + debit, − credit), commission, note
marks.jsonl              per snap: one row per position (mark_net, unrealized) + one "book" row;
                         the EOD snap carries kind="eod" — that row is the day's equity mark
funnel.jsonl             per entry snap and sleeve: candidates → after_dedupe → tickets → attempted → filled
regime.jsonl             per snap: spot, universe, atm_iv, term slopes, skew, GEX/DEX, anything else
surfaces/<date>/<hhmm>.parquet|csv   the chain the strategy saw (strike, expiration, option_type,
                         implied_volatility, delta, gamma, bid, ask, open_interest, spot)
history.csv              optional: date,spot,equity for days before the bot wrote marks
funnel_history.jsonl     optional: funnel rows reconstructed from logs (source=reconstructed)
reference.json           what the pages compare against: net_pace_usd_per_bday, daily_sigma_usd,
                         by_ks (per-spread P&L-vs-return regression and quantiles by moneyness)
regime_history.csv|parquet   the same regime columns over the history the strategy was designed on
```

Field-level detail is the docstring of `deskboard/feeds/statefiles.py`; file names are
overridable (`StateFiles(dir, names={...})`) so an existing bot need not rename anything.
`deskboard record` writes a synthetic 30-day state under `data/demo/state`, regenerated byte for
byte from the seed (CI checks it). `deskboard serve --state data/demo/state` shows the pages;
`deskboard eod --state … --date …` prints or writes the report.

## What the pages read

| page | files | the question it answers |
|---|---|---|
| Pace | marks, history, reference | is the equity path inside the ±1σ/±2σ √n cone of the expected pace? per-open-spread P&L vs underlying return against the reference band; the entry funnel |
| Grid | surfaces, positions | where the legs sit on the strike × expiry grid the strategy saw, with dealer GEX/DEX by strike |
| Regime | regime, regime_history | where today's ATM IV / term slope / skew / GEX / DEX sit in the history the strategy was designed on |
| Metrics | marks, ledger, reference | P&L, hit rate, σ, drawdown, Sharpe **with its standard error**, z vs pace — over a horizon you pick |
| Fills | ledger | every fill vs its decision cross (implementation shortfall in cents), latency |
| Reports | everything | one EOD report per day in the same format, plus a clickable trade log |

Two conventions worth keeping: reconstructed rows carry `source=reconstructed` and a bot row for
the same key wins; and the reference numbers come from the backtest, never fitted to the live days,
so the z-score means what it says.
